# ClickIt-Faster / ClickItMax

Форк [Barragek0/ClickIt](https://github.com/Barragek0/ClickIt). Репозиторий — **ClickIt-Faster**, а плагин в меню, DLL и профиль — **ClickItMax**. Оригинал остаётся отдельно для сравнения. Одновременно включать оба не следует: взаимной блокировки нет.

Быстрый режим кликает ближние предметы без ожидания инвентаря или исчезновения с пола. Недавно кликнутые исключаются по идентичности ground entity на заданное время: по умолчанию 800 мс. Радиус считается по координатам в мире, по умолчанию 20. Дальняя цель удерживается во время подхода; окончание движения освобождает алгоритм для следующего выбора. Новое удержание горячей клавиши может перенаправить уже начатую ручную ходьбу.

Две галочки независимо включают проверку наведения для ближних и дальних кликов. Выключение пропускает обе сверки UIHover соответствующего класса, сохраняя прочие проверки. Ожидание старта движения ограничено 150 мс; дополнительной общей паузы 300 мс нет. Отпускание клавиши прекращает новые команды, но не отменяет уже принятую игрой ходьбу.

**Toggle Item View** периодически дважды нажимает выбранную **Toggle Items Hotkey**, обычно Z. Интервал берётся из **Toggle Item View Interval (ms)**. Первая пара — после полного интервала, не на старте. Пауза после пары тоже настраивается. Пропущенные интервалы не вызывают очередь нажатий.

Выключение «Быстрый подбор предметов» возвращает обычную логику ClickIt внутри форка. Фильтры и доступность предметов учитываются.

Сборка, установка, настройки и тесты: [README.md](README.md). Нужны Windows x64, .NET 10 SDK и совместимый ExileAPI/ExileCore. Логи: `Logs/ClickItMax/pickup-*.jsonl` внутри папки хоста. Отправленный клик сам по себе не доказывает подбор. Эта версия прошла 261 целевой тест и 23 трассы движения; владелец подтвердил успешный live-подбор. Ускорение полного сбора в любой сцене не гарантируется.

## Movement к видимому дальнему луту

В **Controls → Movement: скиллы и приоритет** можно включать отдельные скиллы. Приоритет: Flame Dash → Frostblink → Leap Slam → Whirling Blades → Dash → Blink Arrow → Lightning Warp → Shield Charge. Порог дистанции в мире по умолчанию **60**. Только видимые цели; offscreen pathfinding этот режим не использует. Бинды с Ctrl сохраняются. Для Dash повторите в настройках его игровую галочку Always Attack Without Moving.

У Flame Dash используется общий интервал **850 мс** после ручного или автоматического применения. Ползунок **«Ждать Flame Dash на ходу, мс»** по умолчанию **300**, значение **0** отключает ожидание. Если заряд и остальные проверки API готовы, а до окончания внутреннего интервала осталось не больше выбранного времени, идём к тому же предмету вместо другого скилла. Когда Flame Dash готов, блинкуемся только если цель всё ещё за порогом movement; иначе продолжаем обычный подбор. Восстановление отсутствующего заряда не прогнозируется. Ожидание отменяется при отпускании hotkey, смене контекста, исчезновении/недоступности цели или завершении подхода.

После фактически отправленного отложенного блинка retry-таймер заменённой команды подхода к этой цели снимается, чтобы сразу разрешить клик подбора после приземления. Ограничения повторов остальных предметов сохраняются. Заряд сам по себе не доказывает завершение блинка: отслеживаются перемещение/собственное действие скилла. Неопределённый Lightning Warp блокирует дальнейшее применение Warp до смены зоны.

## Диагностика отказов

Подробные записи сохраняют рамку в момент решения, точки клика/прицеливания, перекрытия и конкретный UI-блокер, окно игры, UIHover и этап отказа. Дополнительные чтения помечены отдельно. Детализация ограничена по частоте; сериализация и запись идут через ограниченную фоновую очередь, которая при переполнении пропускает логи, не ждёт диск. Четыре части ротации на запуск; старые запуски автоматически не удаляются. Перед публикацией своих логов проверьте содержимое.
